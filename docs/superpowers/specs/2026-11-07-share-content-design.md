# 공유 콘텐츠 설계 — 신고가 공유 카드 · 주간 신고가 리포트 · 세로 영상

작성 2026-11-07. 이전 설계: `2026-11-05-supply-area-design.md` 7장(카드 C안), `2026-11-04-canceled-highs-design.md`(신고가·취소 목록, 취소 공유 페이지).
"(Claude 판단)" 표시는 사용자가 위임해 Claude 가 직군 의견(제품·SNS·PR·영상·사실검증·UX·백엔드)을 모아 정한 것이다. 나머지는 사용자 결정.

## 1. 왜 하는가

- 쓰레드·X 에서 본 사람이 **그냥 알고 넘어가거나, 커뮤니티(단톡방·카페·호갱노노 단지 게시판)에 퍼 나르거나, 기자가 인용**하게 한다. 사이트 유입은 그 결과다.
- 신고가 카드를 공유하는 사람은 주로 그 단지 주민(집주인)이다. 단지 단톡방에 올린다.
- 이 사이트의 자산은 "숫자가 맞다"는 신뢰다. 한 번 틀린 이미지가 퍼지면 지워도 캡처가 남는다. 그래서 모든 이미지·영상에 출처·기준을 박고, 사람이 확인한 뒤에만 게시한다.

## 2. 목표 · 비목표 · 안티목표

목표
- 단지 페이지와 `/highs` 에서 신고가·상승 거래를 카드 이미지와 공유 페이지로 공유할 수 있다.
- 매주 목요일 쓰레드·X 에 올릴 "주간 신고가 리포트" 이미지·본문 초안과 세로 영상이 자동으로 만들어진다. 게시는 사람이 한다.
- 기자가 그대로 인용할 수 있는 리포트 페이지(표·인용 문구·CSV)가 있다.

비목표 (이번 범위 아님)
- 로그인·관심단지·알림(웹 푸시·이메일·카카오채널). 순서상 뒤로 미뤘다. 공유 페이지의 "관심단지" 버튼 자리는 그때 붙인다.
- 쓰레드·X·카카오채널 자동 게시(API 연동).
- 재개발 단계 변경·분양권 거래(별도 기능, 10장).

안티목표 (기술적으로 돌아가도 실패로 본다)
- 취소·정정 때문에 틀린 숫자가 담긴 이미지가 나간다.
- "축하", "폭등", "사상 최고", "지금 사야" 같은 해석·선동 문구. 전망·평가를 쓰지 않는다.
- 출처·계약일·zipsise.com 이 빠진 이미지나 영상.
- 특정 단지를 깎아내리거나 호재를 암시하는 표현.

## 3. 제약

- 1인 운영, 비용 0 지향. 기존 구조(GitHub Actions + R2 정적 JSON + Vercel Hobby)만 쓴다. 새 서버 없음.
- **공개 시작 조건**: (1) 취소 데이터 복구 Backfill 완료(`docs/handoff/2026-11-07-canceled-verification.md`), (2) 4장의 판정 보강 반영. 그 전까지는 만들어도 공개 게시·공유 버튼 노출을 하지 않는다(카드 개발·미리보기는 해도 됨).
- 국토부 신고는 계약 후 30일 안에 들어오고, 해제도 나중에 들어온다. 화면의 숫자는 "신고 기준, 이후 바뀔 수 있음"이다.
- 평형 표기는 사이트 표준 "33평 · 전용 84㎡"(추정은 "약 33평")를 따른다.

## 4. 공유 대상 거래와 판정 규칙

카드·리포트·영상의 모든 숫자는 **파이프라인 한 곳**(지금의 `pipeline/highs.py` `record_highs` 를 확장)에서 만들고, 프런트·영상은 다시 계산하지 않는다.

대상 (사용자 결정, 7장 그대로)
- **신고가**: 같은 단지·같은 평형 구분의 이전(계약일이 앞선) 정상 거래 최고가를 넘은 거래. 빨강 "신고가" 배지.
- **상승**: 신고가는 아니지만 같은 단지·같은 평형 구분의 바로 앞 정상 매매보다 비싼 거래. 최소 상승폭 없음. 주황 "상승" 배지. 신고가이면서 직전보다도 오른 건 신고가로만 표시.
- 취소된 거래는 대상이 아니며, 비교 기준에서도 뺀다.

평형 구분 (사용자 결정)
- 화면과 판정은 전용면적 구분(59, 84, 114 …)별이다. 84.97㎡ 와 85.01㎡ 처럼 소수점만 다른 같은 주택형은 하나로 본다. 84A·84B 처럼 타입만 다른 같은 전용 크기도 하나로 본다.
- 지금 코드는 `CAST(area AS INTEGER)` 라서 84.99/85.01 이 갈린다. 구분 방법은 빌더 몫이되, 위 예시가 한 묶음이 되어야 하고, 단지 페이지의 평형 탭 구분과 같아야 한다.

직거래 (사용자 결정)
- 빼지 않는다. `transactions.dealing_gbn = '직거래'` 이면 가격 옆에 회색 "직거래" 표시를 카드·공유 페이지·리포트·영상 모두에 붙인다. 값이 비어 있는 옛 거래는 표시하지 않는다(공유 대상은 최근 거래뿐이라 문제없음).

보류 규칙 (Claude 판단 — 사실검증 직군 제안 중 채택)
- **정정 의심**: 같은 단지·층·계약일에 금액만 다른 정상 거래가 둘 이상이면 그 거래는 공유·리포트에서 뺀다(정정 신고가 새 행으로 들어와 이중으로 잡힐 수 있음).
- **이력 부족**: 같은 평형 구분에 앞선 정상 거래가 3건 미만이면 리포트·영상에서 뺀다(카드 공유는 허용, 첫 거래는 원래 제외).
- **단지 병합 직후**: 최근 7일 안에 `merge_apartments` 로 합쳐진 단지는 그 주 리포트에서 뺀다. 지금은 병합 기록이 없으므로 `merge_apartments` 가 병합할 때 `apartment_merges(keep_id, drop_id, merged_at)` 같은 기록을 남기게 한다.
- **현재 최고가가 아님**: 늦게 신고된 옛 계약은 계약일 순으로는 신고가여도, 그 뒤 계약이 이미 더 높게 거래됐을 수 있다. 리포트·영상에는 "같은 평형 구분에서 지금도 최고가"인 신고가만 넣는다. 카드·공유 페이지는 계약일 기준 정의 그대로 두되 계약일을 크게 보여 준다.
- 채택하지 않은 제안: 등기 완료·계약 후 N일 지난 거래만 공개(신선도를 너무 잃음), 저층 신고가 자동 제외(층은 표기만 함).

각 거래에 실어 보낼 값 (빌더가 JSON 형태 결정)
- 단지 id·이름·지역, 평형 구분, 공급평 표기, 층, 금액, 계약일, 직거래 여부, 배지 종류(신고가/상승), 비교 기준 금액과 차이(이전 최고가 또는 직전 거래), 처음 수집된 시각(`transactions.created_at`), 최근 1년 같은 평형 구분 정상 거래 점 목록(그래프용).

## 5. 신고가 공유 카드와 공유 페이지

기존 취소 공유(`/canceled/[aptId]/[txId]`, `/api/og/canceled/[aptId]/[txId]`)와 같은 방식으로 만든다.

- 주소: `/highs/[aptId]/[txId]` (공유 페이지), `/api/og/highs/[aptId]/[txId]` (카드 이미지 1200×630). 합쳐진 단지는 취소 공유처럼 영구 이동.
- 카드(C안, 7장 그대로): 흰 바탕. 왼쪽 단지명, "33평 · 전용 84㎡", 층, 가격(+ "직거래" 표시), "이전 최고보다 +7,000만" 또는 "직전 거래보다 +3,000만", 배지. 오른쪽 최근 1년 같은 평형 거래 흐름 선과 이번 거래 점. 아래 띠: "국토교통부 실거래가 · 계약 2026.11.03 · 신고 기준 · zipsise.com".
- 공유 페이지: 카드·그래프를 크게, 아래 이 단지 다른 평형 최근 거래, "단지 전체 보기" 버튼. 로그인이 생기면 관심단지 버튼을 여기 붙인다.
- 나중에 취소되면 공유 페이지·카드가 "신고 후 취소"로 바뀐다(취소 공유 페이지와 같은 표현).
- 공유 가능한 거래 범위 (Claude 판단): 계약일이 최근 1년 안인 거래. 공유 페이지는 30일짜리 `highs/recent.json` 이 아니라 단지 JSON 에서 거래를 찾으므로, 파이프라인이 단지 JSON 의 최근 1년 매매 거래마다 배지 종류·비교 기준 금액·차이를 함께 내보낸다(취소 공유가 단지 JSON 을 쓰는 것과 같은 방식).
- 공유 버튼이 붙는 곳: 단지 페이지 매매 거래 목록의 신고가·상승 행, `/highs` 의 각 행. 기존 `ShareButton`(카카오·기기 공유·링크 복사) 재사용, 이미지 저장 추가(호갱노노 게시판용).
- 문구에 "축하" 없음. 공유 제목 예: "OO아파트 33평 12억 5,000만 신고가".

## 6. 주간 신고가 리포트 (쓰레드·X)

게시 시각 (사용자 결정): 매주 **목요일 20:30 KST**. 요일·시각은 첫 4주 성과(저장·공유·링크 클릭)를 보고 바꿀 수 있다.

집계 기간 (Claude 판단)
- "이번 주 새로 공개된 신고가": 지난주 목요일 13시 수집 이후부터 이번 주 목요일 13시 수집까지 **처음 수집된** 신고가(`created_at` 기준). 계약일 기준으로 자르면 늦게 신고된 거래가 영영 빠지기 때문. 각 거래에는 계약일을 따로 적는다.
- 대상은 **신고가만**(상승 배지 거래는 리포트에 넣지 않음 — 너무 많고 순위 의미가 약함). 4장 보류 규칙과 "지금도 최고가" 조건을 통과한 것만.

스냅샷 (Claude 판단)
- 리포트는 목요일 13시 수집 직후 만든 **스냅샷**이다. 이미지·영상·리포트 페이지의 숫자는 이 스냅샷에서만 나온다. 이미지 표기는 "YYYY.MM.DD 13시 수집 기준".
- 게시 전까지(목요일 20:30 전)는 수동 실행으로 다시 만들어 덮어쓸 수 있다. 같은 주에 다시 만들면 같은 N 을 쓴다. 게시 시각이 지나면 그 스냅샷은 고정되고 덮어쓰지 않는다.
- 목요일 19시 수집이 끝나면 스냅샷 거래들의 취소·정정 여부를 자동 재확인해 Actions 요약에 "변동 없음" 또는 바뀐 거래 목록을 낸다. 바뀌었으면 사람이 다시 만들고 나서 게시한다.

순위 기준 (Claude 판단)
- 순위는 **이전 최고가 대비 상승액(원)** 내림차순. 퍼센트는 함께 표기만 한다. 이미지 제목에 "상승액 순"을 적는다(가격 순위로 오해하지 않게).
- 요약 장의 대표 거래와 영상 훅은 "이번 주 신고가 최고액"(가격 기준)이라고 정확히 쓴다. 기준이 다른 두 숫자가 섞여 보이지 않게 문구로 구분한다.
- 지역 TOP 5 는 5건 미만이면 있는 만큼만 보여 준다.

구성 (Claude 판단)
- 시리즈 이름 "주간 신고가 리포트 #N" — 같은 틀을 매주 반복해 "이번 주 거 나왔다"는 기대를 만든다.
- 이미지(1080×1350 세로, 쓰레드 캐러셀 4장 / X 는 1·2장):
  1. 요약: "수도권 신고가 N건 (서울 a · 경기 b · 인천 c)", 이번 주 신고가 최고액 1건.
  2. 서울 상승액 순 TOP 5, 3. 경기 TOP 5, 4. 인천 TOP 5. 한 줄 = 단지명 · 지역 · 공급평/전용 · 층 · 가격 · 이전 최고 대비(금액·%) · 계약일 · (직거래).
- 모든 이미지 하단 고정: "출처 국토교통부 실거래가 · 신고 기준(취소 제외) · 새로 공개 MM.DD~MM.DD · YYYY.MM.DD 13시 수집 기준 · zipsise.com". 마지막 장에 "정정·문의: 이메일 주소" 한 줄.
- 본문: 첫 줄 숫자 요약("이번 주 수도권 아파트 신고가 N건, 최고 OO억"). 해석·전망 없음. 해시태그 0~2개. X 는 링크를 첫 답글에.
- 링크 대상: 리포트 페이지 `/reports/weekly/[N]` (Claude 판단, 영구 주소): 이번 주 표 전체(스냅샷 숫자 + 현재 상태 열: 정상 / 신고 후 취소), 각 행에서 공유 페이지로, "인용하기"(출처·"YYYY.MM.DD 13시 수집 기준"이 들어간 한 문장 복사), CSV 내려받기(계약일·처음 수집 시각·상태 열 포함), 하단에 정정 이력과 문의 이메일. 기자는 근거를 확인할 수 있어야 인용한다.
- 신고가가 3건 미만인 주는 영상은 건너뛰고 이미지 1장만.

주 번호 N (Claude 판단)
- R2 public 에 `v1/reports/weekly/index.json`(발행된 N·주 시작·끝·생성 시각 목록)을 둔다. 새 주의 리포트를 만들 때 마지막 N+1, 같은 주를 다시 만들면 같은 N.
- 게시를 건너뛴 주는 "휴간" 게시 없이 다음 주에 번호를 이어 간다(건너뛴 주의 리포트 페이지는 남아도 됨).

## 7. 세로 영상 (Remotion)

- 9:16 1080×1920, 30fps, **20~25초**, 무음(자막·글자만). 쓰레드·X·릴스·쇼츠 공용 한 파일. 배경음은 나중에 저작권 문제 없는 음원으로만 검토.
- 콘티 (Claude 판단, 영상 직군안):
  - 0–2초 훅: 흰 바탕에 큰 숫자 하나 "이번 주 최고 신고가 38억" + 단지명. 낚시·질문형 문구 없음.
  - 2–4초: "수도권 신고가 N건".
  - 4–16초: TOP 3, 장면당 4초. 카드와 같은 배치(왼쪽 단지·평형·가격·계약일, 오른쪽 1년 흐름 선이 그려지고 점, 배지).
  - 16–22초: 엔딩. zipsise.com, "주간 신고가 리포트 #N", 출처·집계 기준일.
  - 전환은 짧은 밀기·컷만.
- 전 장면 하단 띠: "국토교통부 실거래가 · 신고 기준 · zipsise.com". 각 장면 가격 아래 계약일. 플랫폼 UI 에 가리지 않게 하단 약 250px·오른쪽 약 150px 비움.
- 색·글꼴·배지 문구는 카드(Next.js)와 영상(Remotion)이 **같은 토큰 파일**을 쓴다.
- TOP 3 는 리포트와 같은 기준(수도권 전체 상승액 순). 훅만 신고가 최고액.
- Remotion 라이선스: 개인·소규모는 무료로 알고 있으나 확인 필요. **착수 전 확인이 막는 조건**이다(확인 결과를 문서에 기록).
- 렌더가 실패하면 그 주는 이미지·본문만으로 게시한다. 영상 실패가 리포트를 막지 않는다.

## 8. 만들기 · 확인 · 게시 흐름

- 새 워크플로 `weekly-report.yml` (Claude 판단): 목요일 13시 수집이 끝난 뒤(같은 `collect` concurrency 그룹 또는 수집 워크플로의 목요일 분기 — 빌더 몫) 실행.
  1. 정본 DB 에서 리포트 JSON 생성 → R2 public(`v1/reports/weekly/N.json`) 에 올림 → 리포트 페이지가 읽음.
  2. 이미지 4장(PNG)과 본문 초안(텍스트) 생성.
  3. Remotion 렌더 → MP4.
  4. 결과물을 한곳에 모음(Actions artifact 또는 R2 private — 빌더 몫)과 확인 체크리스트를 GitHub Actions 요약에 출력.
- 사람 확인 (게시 전 필수, Claude 판단): 워크플로가 **대조표**를 Actions 요약에 미리 채워 사람은 눈으로만 확인한다. 1인 운영으로 매주 30분 안에 끝나야 한다.
  - 대조 대상: 상위 3건 + 각 지역 1위 + 지역별 건수. 각 행에 단지·층·전용·금액·계약일과 국토부 실거래가 공개시스템에서 찾을 조건(시군구·단지명·계약월)을 적는다.
  - 19시 재확인 결과("변동 없음" 또는 바뀐 거래).
  - 기간·수집 기준 표기.
- 게시: 사람이 쓰레드(예약 게시 가능)·X 에 직접 올림. 카카오채널 소식은 채널 개설 뒤 같은 이미지로 수동 게시(알림 단계에서 다룸).
- 게시 뒤 정정 (Claude 판단): 매일 수집 때 최근 2주 리포트 스냅샷 거래들의 취소·정정을 점검해, 생기면 Actions 요약에 띄운다. 사람이 해당 쓰레드·X 게시물에 정정 답글을 달고, 리포트 페이지는 그 행을 "신고 후 취소"로 바꾸고 상단 정정 이력에 남긴다(이미지는 고칠 수 없으므로).

공개 게이트 (Claude 판단)
- 프런트: 환경 변수 플래그(기존 `SUPPLY_ENABLED` 와 같은 방식)가 꺼져 있으면 신고가 공유 버튼과 리포트 페이지 링크를 숨긴다. 공유·리포트 페이지는 지금 취소 공유처럼 `noindex`.
- 주간 워크플로: 저장소 변수가 꺼져 있으면 일정 실행을 건너뛰고 수동 실행만 된다.
- Backfill 완료와 4장 판정 보강을 사람이 확인한 뒤 두 플래그를 켠다.

## 9. 성공 지표 (무료 측정)

- 공유 페이지·리포트 페이지 방문 수(UTM 으로 쓰레드/X/카카오/링크 복사 구분, 기존 분석 도구).
- 공유 버튼 누른 수(단지 페이지·/highs).
- 쓰레드·X 게시물별 저장·공유·링크 클릭(플랫폼 인사이트, 수기 기록).
- 목표값은 4주 관측 뒤 정한다. 팔로워 수는 보조.

  - 정비구역 CSV(현재 2026-05-18 한 번 받음)를 주기적으로 다시 받아 "현 사업추진단계" 변경을 잡는다.
