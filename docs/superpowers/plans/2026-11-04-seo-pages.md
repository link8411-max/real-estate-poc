# 검색 입구 늘리기 (동 페이지 + 최근 신고가) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 단톡방·채널 없이 검색으로 유입을 늘린다. 사람들이 실제로 치는 "구갈동 아파트 시세", "OO구 신고가" 같은 검색어에 맞는 페이지를 이미 가진 데이터로 자동 생성한다.

**Architecture:** 동 페이지는 기존 `v1/region/{code}.json`(단지마다 `dong` 있음)만으로 만든다(파이프라인 변경 없음). 최근 신고가는 `canceled_highs`와 같은 방식으로 파이프라인이 매일 `v1/highs/recent.json`을 내보내고, 프론트가 `/highs` 페이지와 지역·동 페이지 섹션으로 보여 준다. 모든 페이지는 ISR(3600).

## Global Constraints
- 운영비 0원: 새 서버·DB 없음. R2 정적 JSON + Vercel ISR.
- "신고가" 정의(취소된 신고가와 같은 규칙, 취소 아닌 거래에 적용): 취소되지 않은(`cancel_date IS NULL`) 매매 T가, 같은 단지·같은 평형 묶음(`CAST(area AS INTEGER)` / `areaGroup`)에서 계약일이 **엄격히 이전**이고 취소되지 않은 거래들의 최고가보다 **엄격히 크면** 신고가. 이전 거래 없으면 아님.
- 기간: 계약일 기준 최근 30일(KST 오늘 기준). 신고 지연이 있으므로 매일 갱신.
- 날짜 표시는 `formatDeal`, 금액은 기존 `formatPrice`/`formatManwon`.
- 상단 메뉴(이미 6개)는 늘리지 않는다. 진입은 홈 카드·지역/동 페이지·`/canceled` 링크·사이트맵.
- 테스트: Python `.venv/bin/python -m pytest -q`, 프론트 `cd frontend && npx vitest run && npx tsc --noEmit && npx eslint src && npx next build`.

## Review Focus
1. 동 이름에 괄호·숫자·공백이 있어도 URL이 깨지지 않는다(인코딩·디코딩 왕복).
2. 단지가 1개뿐인 동, 좌표 없는 단지 → 페이지가 깨지지 않는다.
3. `highs/recent.json`이 아직 없을 때(첫 배포 직후) `/highs`와 섹션은 빈 상태로 렌더(500 아님).
4. 같은 날 같은 평형 여러 건 → 같은 날 거래끼리는 비교하지 않는다(정의대로).
5. 사이트맵 전체 URL 수가 5만 개를 넘지 않는다(현재 ~2.2만 + 동 ~1.5천 + 1).

### Task 1: 동 단위 페이지 `/region/[code]/[dong]`
**Files:** Create `frontend/src/app/region/[code]/[dong]/page.tsx` (ISR, `generateStaticParams` 빈 배열, `generateMetadata`); Modify `frontend/src/app/region/[code]/page.tsx`(동 목록 칩 링크 추가), `frontend/src/app/sitemap.ts`(동 URL), `frontend/src/lib/seo.ts`(동 제목·설명·href 헬퍼), 단지 페이지 breadcrumb에 동 단계 추가(`aptCrumbs`).
- 제목(그대로): `{동} 아파트 실거래가 · 시세 | {시군구 이름}` (기존 `firstFit`/MAX_TITLE 규칙으로 길이 맞춤). 설명: `{시군구} {동} 아파트 {N}개 단지 실거래가. 최근 매매 {대표 2~3개 단지 이름·가격}.`
- 본문: H1 `{동} 아파트 실거래가`, 요약(단지 수, 최근 30일 거래 수가 데이터로 가능하면 표시, 아니면 생략), 단지 목록(이름·준공·최근 매매가·날짜·최근 전세, 최근 거래일 최신순), 각 단지 링크, 동 미니 지도(기존 `MiniMap`을 그 동 단지 좌표 평균 중심, 레벨 5, `/map?lat&lng&level=5` 링크; 좌표 없으면 생략), "이 동 최근 신고가" 섹션은 Task 2 이후 붙인다(지금은 자리 없음).
- URL: `encodeURIComponent(dong)`; 존재하지 않는 동 → `notFound()`. JSON-LD BreadcrumbList.
- [ ] 테스트 먼저(제목·설명 형식, 인코딩 왕복, 없는 동 404, 사이트맵 포함, 지역 페이지 칩 링크, 단지 breadcrumb 동 단계) → 구현 → 전체 확인 → 커밋 `feat(web): 동 단위 아파트 시세 페이지`

**Files:** Modify `pipeline/canceled.py` 옆에 `pipeline/highs.py`(새) — `record_highs(conn, since: str) -> list[dict]`(키: canceled_highs와 같되 `cancel_date`·`days_to_cancel` 없음: `tx_id, apt_id, apt_name, region_name, city, lawd_cd, dong, area, area_group, floor, amount, prev_max, jump, jump_pct, deal_date`), `build_highs_recent(conn, today) -> {generated_at, since, items}`; `pipeline/export_json.py`에서 매번 `v1/highs/recent.json` put. 프론트: `lib/types.ts`·`lib/data.ts`(`fetchHighsRecent`), `app/highs/page.tsx`(ISR, 메타), 컴포넌트 `HighsBoard`(헤드라인 `최근 30일 신고가 {N}건`, 지역 필터 전체/서울/경기/인천, 상승률 큰 순 TOP 3 큰 카드 `+{jump_pct}%`·`{formatPrice(amount)}`, 아래 목록 최신순), 지역 페이지와 동 페이지에 "최근 신고가" 섹션(해당 lawd_cd/dong 항목 최대 5개 + `/highs` 링크), 홈에 카드 `최근 30일 신고가 {N}건` → `/highs`, `/canceled` 페이지에 `/highs` 링크 한 줄, 사이트맵 `/highs`.
- 성능: 매일 실행(5백만 건). 최근 30일 계약 거래만 고른 뒤 각 행에 인덱스 조회(`idx_transactions_apt_date`). 실제 DB 복사본에서 10초대 목표.
